Registro de la hora de llegada desde el celular

El celular manda la hora a un Worker de Cloudflare y la extensión la lee al cargar el reporte. Es necesario porque la VPN impide abrir el reporte desde el celular. 

Celular → Worker de Cloudflare (KV) ← Extensión (computadora con VPN)
  • El servidor pone la hora, así que no depende del reloj del celular.
  • Guarda una llegada por día (se borran solas a las 5 semanas).
  • Si ya hay una hora ese día, el servidor responde exists y hay que pedir sobrescribirla (force=1).
  • Las marcas del celular solo aplican al primer row. Para rellenar el formulario de hoy debe ser AM.
  • Cloudflare KV puede tardar hasta un minuto en reflejar un cambio.

Antes de empezar

Costo: el plan gratuito de Cloudflare alcanza de sobra para este uso y no pide tarjeta. Confirma los límites vigentes en la página de precios de Cloudflare.

Prueba la red del trabajo primero. Con la VPN activa, abre en Chrome la URL del Worker cuando la tengas. Si responde unauthorized, la red llega y todo está bien. Si no carga, la red bloquea workers.dev y esta solución no funcionará desde esa computadora.

Parte 1: Crear el Worker en Cloudflare

El código está en worker/worker.js (dentro de la extensión). Ábrelo, selecciona todo y copia.

  1. En el panel de Cloudflare ve a Workers & Pages → Create.
  2. No subas archivos. El cargador de archivos es el de Pages y falla con "This uploader does not yet support projects that require a build process".
  3. Las plantillas destacadas (Astro, React Router, Vite React, etc.) no sirven. Busca la plantilla Hello World entre las opciones.
  4. Ponle el nombre horas-llegada y pulsa Deploy.
  5. Pulsa Edit code, borra el código de ejemplo, pega el código copiado y pulsa Deploy de nuevo.

Parte 2: Crear el namespace de KV y vincularlo

El dropdown del binding solo deja elegir un namespace que ya existe. No permite crear uno, así que se crea primero por separado.

  1. Crea un namespace de KV desde la sección de almacenamiento del panel (menú Storage & Databases → KV, el nombre puede variar). Por ejemplo horas-llegada.
  2. Abre el Worker → Settings → Bindings → Add.
  3. En la lista que aparece, elige KV namespace. La lista abre con D1 database seleccionado: no es esa.
  4. En Variable name escribe exactamente ARRIVALS (mayúsculas). El código usa ese nombre.
  5. Elige el namespace creado y guarda.

Parte 3: Variables y secretos

En el Worker → Settings → Variables and Secrets:

NombreValorTipo
KEYUna cadena larga y aleatoriaSecret
TZTu zona horaria, por ejemplo America/ChihuahuaTexto

Después de agregar el binding y las variables, pulsa Deploy otra vez para que se apliquen.

Parte 4: Obtener la URL y probar

La URL del Worker aparece en el Overview, en Domains & Routes (el nombre puede variar). Tiene la forma https://horas-llegada.TU-SUBDOMINIO.workers.dev. El dominio workers.dev debe estar activado.

Prueba desde la terminal, sustituyendo la URL y la llave:

curl -s "https://TU-URL.workers.dev/arrival?key=TU_KEY"
curl -s -X POST "https://TU-URL.workers.dev/arrive?key=TU_KEY"
curl -s -X POST "https://TU-URL.workers.dev/arrive?key=TU_KEY"
curl -s "https://TU-URL.workers.dev/arrivals?key=TU_KEY"
RespuestaSignificado
{"ts":null}Todo bien. Todavía no hay hora registrada hoy.
{"status":"saved","ts":...,"time":"..."}Registró la hora (primer POST).
{"status":"exists",...}Ya había hora hoy (segundo POST).
{"days":{"2026-11-03":...}}Historial de llegadas (lo que lee la extensión).
unauthorizedLa KEY no coincide con la guardada en el Worker.
Error 1101 de CloudflareFalta el binding ARRIVALS, o falta desplegar.

Ojo: la prueba deja registrada una llegada de hoy. Se borra sola con el tiempo, y la extensión la ignora si es PM.

Parte 5: Configurar la extensión

  1. Abre el popup de la extensión. En Registro hora de llegada, escribe la URL del Worker en Endpoint del celular y la llave en Key.
  2. Recarga el reporte. Si ya hay una hora de llegada AM registrada hoy, las listas se llenan solas.

Parte 6: Acceso directo en Android (HTTP Shortcuts)

La app gratuita se llama HTTP Shortcuts (Play Store). Sustituye TU-URL y TU_KEY.

Acceso 1: Llegada

  1. Pulsa + → crear un acceso directo HTTP Shortcut (Regular).
  2. Nombre: Llegada. Método: POST.
  3. URL: https://TU-URL.workers.dev/arrive?key=TU_KEY
  4. En Manejo de respuesta:
    • Al éxito: Mostrar respuesta.
    • Al fracaso: Mostrar mensaje de error detallado. Un 409 cuenta como fallo, y la versión detallada incluye el cuerpo con la hora ya registrada.
  5. Guarda.

Acceso 2: Llegada (sobrescribir)

Igual, pero con la URL https://TU-URL.workers.dev/arrive?key=TU_KEY&force=1.

Para la pantalla de inicio, mantén pulsado cada acceso dentro de la app y elige Colocar en pantalla de inicio. Uso: toca Llegada. Si ya había hora verás exists con la hora registrada; para corregirla, toca Llegada (sobrescribir).

Parte 7: Acceso directo en iOS (Atajos)

No probado. Los nombres de las acciones pueden variar según la versión de iOS.
  1. Abre Atajos, pulsa + y nómbralo Llegada.
  2. Obtener contenido de URL, con la URL https://TU-URL.workers.dev/arrive?key=TU_KEY. En Mostrar más, método POST.
  3. Obtener valor del diccionario para la clave status del resultado.
  4. Obtener valor del diccionario para la clave time del resultado.
  5. Si el valor de status es exists:
    1. Mostrar alerta: título Ya registraste a las [time], mensaje ¿Sobrescribir con la hora actual?. Si cancelas, el atajo se detiene.
    2. Obtener contenido de URL con ...&force=1 y método POST.
    3. Obtener valor del diccionario para la clave time del resultado anterior.
    4. Mostrar notificación: Llegada actualizada: [time].
  6. En el Si no: Mostrar notificación con Llegada registrada: [time].
  7. Para la pantalla de inicio: detalles del atajo → Añadir a pantalla de inicio.
La llave queda dentro de la URL de los accesos directos. No compartas capturas ni los exportes.
